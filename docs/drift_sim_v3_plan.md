# План генератора DriftSim v3

## Цель

V3 исправляет ошибки геометрии и идентификации трубок, не меняя физическую модель событий. Старые `driftsim_v1.py` и `driftsim_v2.py` остаются без изменений, поэтому старые наборы данных, эксперименты и чекпоинты можно воспроизводить как раньше.

V3 сохраняет:

- прямолинейное движение трека от общей вершины события;
- прежние диапазоны координат вершины, числа треков, `pt`, `phi` и `theta`;
- восемь плоскостей `X/Y/U/V/X/Y/U/V` между `z=0` и `z=240 мм`;
- квадратную активную область `|x| < 750 мм`, `|y| < 750 мм`;
- шаг трубок `10 мм`;
- эффективность `1.0`, отсутствие шумовых хитов и нулевой заряд по умолчанию.

`pt` и `charge` по-прежнему сохраняются как truth-поля, но не влияют на прямую траекторию. Добавление магнитного поля, кривизны, рассеяния, шума и неидеальной эффективности не входит в исправление v3: это отдельное изменение физической модели.

Чтобы одинаковый seed воспроизводил не только распределение, но и сами truth-точки v1/v2, верхняя граница `phi` сохранена в конфиге как точное legacy-значение `2 × 3.14156 = 6.28312`. Геометрический код использует точные нормали из `sqrt(2)`; legacy-приближение π не используется для определения U/V-проволок.

## Ошибки v1/v2 и исправления v3

### 1. Неверная геометрия U/V

В v1/v2 номер наклонной трубки вычислялся формулой, которая давала отрицательные сырые номера. После `% 1000` они превращались в значения примерно `682..894`, а восстановленные `x0/y0` могли оказываться на расстоянии `8–11 м` от детектора. Эти точки не являлись физическими координатами проволок.

V3 задаёт каждую плоскость единообразно через единичную нормаль `n` и измеряемую координату `q = n · (x, y)`. Центр ближайшей трубки определяется округлением `q` к сетке с шагом `10 мм`; `x0/y0` — ближайшая к началу координат точка соответствующей проволоки. Для X/Y и U/V используется один и тот же алгоритм.

### 2. Коллизии target-классов

В старом препроцессинге применялось `% 151`. Наклонная проекция квадрата шириной `1500 мм` имеет ширину `1500√2 ≈ 2121 мм`, поэтому физически ей требуется 213 позиций с шагом `10 мм`. Сведение этих позиций к 151 классу склеивало разные трубки: в каждой U/V-плоскости было 60–62 коллизии.

V3 не применяет modulo. Число трубок выводится из геометрии:

Для X/Y legacy-индексы лежали в диапазоне `75..225`; `% 151` не создавал коллизий, но разрывал естественный порядок на границе `150 → 0`. В v3 локальный индекс монотонно идёт от 0 на координате `-750 мм` до 150 на `+750 мм`. Для U/V исправляется и порядок, и сама потеря уникальности.

|---:|:---:|---:|---:|:---|
| 1 | X | 0.000 | 151 | 0–150 |
| 2 | Y | 34.286 | 151 | 151–301 |
| 3 | U | 68.571 | 213 | 302–514 |
| 4 | V | 102.857 | 213 | 515–727 |
| 5 | X | 137.143 | 151 | 728–878 |

| 8 | V | 240.000 | 213 | 1243–1455 |

Итого модель v3 предсказывает 1456 уникальных физических классов.

### 3. Две несовместимые сетки z

В v1/v2 truth-точки строились на восьми z-плоскостях `0..240 мм`, а координата проволоки восстанавливалась по другой сетке из девяти значений. Поэтому `z` траектории мог не совпадать с `z0` хита.

V3 создаёт одну сетку из восьми плоскостей. Та же `z` используется при экстраполяции трека, выборе станции и записи `z0`.

### 4. Неоднозначные идентификаторы

V1/v2 смешивали номер станции, сырой номер проволоки и преобразованный класс. В v3 они разделены:

- `station`: физическая плоскость, 1–8;
- `local_tube_id`: индекс внутри плоскости, начиная с нуля;
- `wireid = station * 1000 + local_tube_id`: читаемый составной идентификатор;
- `tube_class_id`: плотный глобальный target модели, 0–1455;
- `plane`: X, Y, U или V.

Препроцессор проверяет согласованность этих полей и завершает работу с ошибкой при выходе за геометрию. Неверные идентификаторы больше не исправляются неявным modulo.

### 5. Номер станции зависел от наличия хита

В старом цикле номер станции увеличивался только после принятого хита. Это не проявлялось при эффективности `1.0`, но давало бы неверную станцию при пропущенных хитах.

В v3 станция является свойством плоскости и не зависит от эффективности или прохождения трека через активную область.

### 6. Невоспроизводимый и неописанный формат

V3 использует отдельный локальный генератор случайных чисел, явный seed и сохраняет:

- заголовок и `schema_version=3` в TSV;
- полную нормализованную конфигурацию;
- геометрию каждой станции и общее число классов в `metadata.yaml`;
- SHA-256 файла данных;
- `seed.lock`.

Повторный запуск с тем же конфигом и seed создаёт байт-в-байт одинаковый TSV.

## Совместимость и сохранение старых версий

- `scripts/driftsim_v1.py` и `scripts/driftsim_v2.py` не изменяются.
- Legacy-режим препроцессора остаётся режимом по умолчанию и продолжает читать старые headerless TSV.
- V3 включается явно параметром `--schema-version v3` и требует `metadata.yaml`.
- Старый чекпоинт с 1208 выходами нельзя корректно использовать для v3 с 1456 классами. Для сравнения старых моделей нужно оставить фиксированный legacy test set; для v3 следует обучить отдельную модель и использовать отдельный фиксированный v3 test set.
- Смешивание файлов v1/v2 и v3 в одном cache запрещено схемой и проверками.

## Порядок перехода

1. Сгенерировать небольшой v3 sample и проверить инварианты геометрии.
2. Препроцессировать его в отдельный cache и выполнить короткий train/validation smoke test.
3. Сгенерировать фиксированный v3 benchmark на 100 000 событий с отдельным seed; сохранить TSV, конфиг, metadata и hash.
4. Сгенерировать независимый train set v3 и обучить модель с `num_tubes=1456`.
5. Сравнивать модели только внутри одной схемы данных; в отчётах всегда указывать schema, seed и SHA-256.

## Критерии приёмки

- для каждой строки `z == z0` и станция соответствует своей z-плоскости;
- `|x| < 750 мм`, `|y| < 750 мм`, `0 ≤ dr ≤ 5 мм`;
- координата truth-точки и координата центра проволоки различаются ровно на signed drift вдоль нормали;
- все `local_tube_id`, `wireid` и `tube_class_id` находятся в заявленных диапазонах;
- отображение `(station, local_tube_id) → tube_class_id` взаимно однозначно;
- одинаковый seed даёт одинаковый SHA-256;
- legacy preprocessing продолжает работать без изменения команды;
- v3 cache проходит хотя бы один train и validation batch без ошибок размерности.

## Команды

Генерация:

```bash
python scripts/driftsim_v3.py -n 100000 -o outputs/test_v3_100k --seed 424242
```

Препроцессинг:

```bash
python scripts/preprocess_drift_sim.py --schema-version v3 --input-dir outputs/test_v3_100k --output-dir outputs/test_v3_100k_cache
```

Обучение на отдельном v3 cache:

```bash
python train.py dataset=drift_sim_v3
```
